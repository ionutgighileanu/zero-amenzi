## 5. Schema DB

Există 3 migrări SQL în `supabase/migrations/`:

1. **`20260720143335_schema.sql`** — 9 tabele: `users`, `organizations`, `memberships`, `vehicles`, `vehicle_docs`, `drivers`, `driver_certs`, `alert_types`, `notifications_log`. Constrângere `owner_id XOR org_id` pe `vehicles` și `alert_types`.
2. **`20260720143336_functions.sql`** — `is_org_member`/`is_org_admin` (helpers RLS), trigger `on_auth_user_created` (sincronizare `auth.users` → `public.users`), trigger `on_organization_created` (owner devine automat membership).
3. **`20260720143337_rls.sql`** — RLS activat pe toate cele 9 tabele, cu policies pe fiecare (select/insert/update/delete), fără bypass — respectă cerința explicită din CLAUDE.md.

Schema corespunde fidel schiței din CLAUDE.md, plus un tabel suplimentar (`alert_types`) necesar pentru funcția de alerte custom, nemenționat explicit în CLAUDE.md dar cerut de UI existent.

**Status aplicare**: vezi secțiunea 3 — neconfirmat pe proiectul live.

## Rezumat

**Ce e solid:** fundația tehnică — autentificare reală, schema DB cu RLS corect, CRUD complet pe vehicule/șoferi/documente pentru ambele segmente (B2C/B2B), soft-delete cu undo, UI polish (motion, contrast, empty states). Codul trece type-check și build fără erori.

**Ce lipsește pentru un MVP monetizabil conform CLAUDE.md:** cele trei bucăți care transformă produsul din "tracker de documente" în "SaaS freemium cu venit" — (1) motorul de alerte real (email/SMS), (2) integrarea broker RCA/CASCO cu bani reali, (3) gating-ul freemium (limita de 1 vehicul + upgrade PRO). Pe lângă asta, cele 4 pagini publice SEO sunt complet absente, ceea ce taie principalul canal de achiziție organică descris în CLAUDE.md.

**Blocaj imediat de verificat:** confirmă manual în Supabase SQL Editor că toate cele 3 migrări au rulat cu succes — nu am putut verifica automat din acest mediu (fără acces la rețea).
